# Public API

The default export is the styled automatic editor. `UnstyledHexEditor` is the automatic editor with inline layout. `BaseHexEditor` and `UnstyledBaseHexEditor` require explicit geometry.

Start with **AutoSizeHexEditorProps**, **HexEditorProps**, and **HexEditorHandle** for the component contract. **BaseHexEditorProps** contains their shared options. All four components forward the same handle. The styled wrappers also support styled-components v5's theme and polymorphic component options; their generated wrapper signatures are secondary to these prop interfaces.

Hex paste accepts complete, case-insensitive byte pairs, contiguous or separated by whitespace, with optional leading/trailing whitespace: `ABcd` and `AB CD` are valid; tabs and newlines between pairs are also accepted. Whitespace within a pair (`A B`), prefixes (`0xAB`), punctuation (`AB,CD`), invalid characters and incomplete pairs (`AB C`) reject the entire paste before any writes, including text beyond the buffer end. Rejection preserves bytes, selection and any pending nibble. Optional `onPasteError(error: Error)` receives a regular `Error` instance once. Its `message` provides a default English explanation for the caller to display or replace: "Invalid hex input. Use complete byte pairs, optionally separated by whitespace—for example, AB CD." Empty or whitespace-only hex input is ignored. Read-only paste does not invoke this callback. In overwrite mode, Hex or ASCII paste that exceeds the remaining buffer length (including non-empty paste into empty data) is rejected entirely with the message "Paste exceeds the remaining buffer length." No bytes, selection or pending nibble change on rejection. Exact-fit paste is accepted, even if it extends beyond the selected range. Insert mode replaces the selection or inserts at the caret. With `onEdit`, ASCII paste accepts only U+0000 through U+00FF.

Native copy uses plain text: Hex produces contiguous lowercase byte pairs; ASCII maps each byte to the corresponding Unicode character U+0000 through U+00FF, without decoding UTF-8 sequences. The single-line input strips CR/LF before native ASCII copy, so use Hex copy for a lossless representation of binary data. Forward/backward selections produce the same clipboard text. An empty selection leaves the clipboard unchanged. Cut requests removal in writable insert mode and preserves bytes in overwrite or read-only mode.

### Controlled edits and history

Set `onEdit` to receive one `HexEditorEdit` per completed keyboard or clipboard edit. Apply it as a single replacement by keeping the bytes before `offset`, adding `insert`, and keeping the bytes after `offset + deleteCount`. To move the caret after accepting the operation, pass the updated `data` and the original request as `appliedEdit` in the same render. If you reject the request, leave both props as they were. A delayed acceptance advances the caret only if it is the latest request and the user has left the selection alone. Check for stale data before accepting a delayed edit.

`editBehavior="insert"` lets typing and paste replace a selection or insert at the caret. Delete removes the next byte or the selection, and Backspace removes the preceding byte or the selection. A collapsed range can sit at `data.length` and an empty buffer has caret zero. Overwrite remains the default. `onSetValue` continues to serve callers using fixed-length editing and imperative `setValue` requests.

`getSelection()` reads the current start, exclusive end, direction, caret and active pane. `onSelectionChange` observes changes after mount. Restore those values with `setSelectionRange(start, end, direction, takeFocus, pane)`. For nonempty ranges, the caret is the start of a backward range or the exclusive end of a forward range.

The owner supplies history through `onUndo` and `onRedo`. Ctrl/Cmd+Z requests undo, Ctrl/Cmd+Shift+Z requests redo, and Ctrl+Y also requests redo on non-Mac platforms. Store the before/after bytes and selections from each accepted request, discard the redo stack after a new edit, and restore the relevant selection once the restored data is rendered. Two Hex digits complete one edit. Read-only mode blocks history shortcuts from changing bytes.

See the [guide and live demo](/react-hex-editor/index.html#guide) for controlled writes, selection, sizing, themes and known behavior limitations. This is unreleased development documentation for the independent sashauly fork; the upstream npm package is a different distribution.
