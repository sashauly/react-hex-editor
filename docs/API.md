# Public API

The default export is the styled automatic editor. `UnstyledHexEditor` is the automatic editor with inline layout. `BaseHexEditor` and `UnstyledBaseHexEditor` require explicit geometry.

Start with **AutoSizeHexEditorProps**, **HexEditorProps**, and **HexEditorHandle** for the component contract. **BaseHexEditorProps** contains their shared options. All four components forward the same handle. The styled wrappers also support styled-components v5's theme and polymorphic component options; their generated wrapper signatures are secondary to these prop interfaces.

Hex paste accepts complete, case-insensitive byte pairs, contiguous or separated by whitespace, with optional leading/trailing whitespace: `ABcd` and `AB CD` are valid; tabs and newlines between pairs are also accepted. Whitespace within a pair (`A B`), prefixes (`0xAB`), punctuation (`AB,CD`), invalid characters and incomplete pairs (`AB C`) reject the entire paste before any writes, including text beyond the buffer end. Rejection preserves bytes, selection and any pending nibble. Optional `onPasteError(error: Error)` receives a regular `Error` instance once. Its `message` provides a default English explanation for the caller to display or replace: "Invalid hex input. Use complete byte pairs, optionally separated by whitespace—for example, AB CD." Empty or whitespace-only hex input is ignored. Read-only paste does not invoke this callback. In both Hex and ASCII modes, paste that exceeds the remaining buffer length (including non-empty paste into empty data) is rejected entirely with the message "Paste exceeds the remaining buffer length." No bytes, selection or pending nibble change on rejection. Exact-fit paste is accepted, even if it extends beyond the selected range. Editing never grows the buffer.

Native copy uses plain text: Hex produces contiguous lowercase byte pairs; ASCII maps each byte to the corresponding Unicode character U+0000 through U+00FF, without decoding UTF-8 sequences. The single-line input strips CR/LF before native ASCII copy, so use Hex copy for a lossless representation of binary data. Forward/backward selections produce the same clipboard text. An empty selection leaves the clipboard unchanged. Native cut currently copies the selection without removing or zeroing any source bytes, including in read-only mode; structural cut remains tracked in [#12](https://github.com/sashauly/react-hex-editor/issues/12) and depends on [#8](https://github.com/sashauly/react-hex-editor/issues/8).

See the [guide and live demo](/react-hex-editor/index.html#guide) for controlled writes, selection, sizing, themes and known behavior limitations. This is unreleased development documentation for the independent sashauly fork; the upstream npm package is a different distribution.
