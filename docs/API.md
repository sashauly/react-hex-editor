# Public API

The default export is the styled automatic editor. `UnstyledHexEditor` is the automatic editor with inline layout. `BaseHexEditor` and `UnstyledBaseHexEditor` require explicit geometry.

Start with **AutoSizeHexEditorProps**, **HexEditorProps**, and **HexEditorHandle** for the component contract. **BaseHexEditorProps** contains their shared options. All four components forward the same handle. The styled wrappers also support styled-components v5's theme and polymorphic component options; their generated wrapper signatures are secondary to these prop interfaces.

Hex paste accepts complete, case-insensitive byte pairs, contiguous or separated by whitespace, with optional leading/trailing whitespace: `ABcd` and `AB CD` are valid; tabs and newlines between pairs are also accepted. Whitespace within a pair (`A B`), prefixes (`0xAB`), punctuation (`AB,CD`), invalid characters and incomplete pairs (`AB C`) reject the entire paste before any writes, including text beyond the buffer end. Rejection preserves bytes, selection and any pending nibble. Optional `onPasteError(error: Error)` receives a regular `Error` instance once. Its `message` provides a default English explanation for the caller to display or replace: "Invalid hex input. Use complete byte pairs, optionally separated by whitespace—for example, AB CD." Empty or whitespace-only hex input is ignored. ASCII paste and read-only paste do not invoke this callback. Valid paste still overwrites only the bytes that fit in the remaining buffer.

See the [guide and live demo](/react-hex-editor/index.html#guide) for controlled writes, selection, sizing, themes and known behavior limitations. This is unreleased development documentation for the independent sashauly fork; the upstream npm package is a different distribution.
